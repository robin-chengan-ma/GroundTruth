# 稽核與正確率總覽 討論紀錄

> 同一功能的多次討論都寫在同一個檔案，依時間往下附加新段落，不要開新檔案。

## 2026-08-24 [標籤：使用者] 是否需要一個頁面呈現「AI 與真實資料比對」的正確率

**狀態**：accepted

**背景**：原始規格只有「稽核 log 查詢頁」，可以查單筆紀錄，但沒有任何統計/量化呈現，無法回答「這套遮罩＋驗證機制實際運作得好不好」這個問題。

**討論內容**：每次幻覺驗證、每次供應商比對，都已經寫進稽核 log（FR-6、FR-11），資料基礎已經存在，只是缺一層統計聚合。討論後認為這個頁面跟專案核心賣點（AI 輸出可信度）直接相關，值得獨立列一個功能區塊，而不是塞進既有的稽核 log 查詢頁面裡混著看。

**決策**：
1. 新增獨立功能區塊「稽核與正確率總覽」，統計來源全部是既有稽核 log 資料，不需要新增資料表。
2. 頁面呈現三類統計：
   - 幻覺驗證通過率（一致 vs 不一致的比例）
   - 供應商比對準確率（精確比對／模糊比對／查無供應商三種情況的次數與比例）
   - 複核佇列處理狀況（待處理筆數、已處理筆數，處理結果分布）
3. 權限比照稽核 log，僅管理員可見。

**理由**：這個頁面把「攔截問題案件」的機制從單次事件提升成可持續監控的量化指標，對於展示「AI 導入企業系統要能持續監控、不是做完驗證就結束」這個主題有直接幫助，且不需要新增資料模型，實作成本低。

**後果**：
- Django 需要提供一個統計聚合 API（依稽核 log 計算比例），前端 Vue 頁面呼叫呈現。
- 統計期間篩選（例如本週/本月）留到實作階段再定，SPEC 先定案「有這個頁面、呈現哪三類統計」。

## 2026-09-02 [標籤：使用者] 正式納入 Phase 6

**狀態**：accepted

**背景**：此功能已於 2026-08-24 定案，但 SPEC 的實作階段長期保留「Phase 1：待補」，建立 Phase 5～7 Roadmap 時也未排入任何階段。

**討論內容**：資料來源與正式採購 API 契約已於新核心建立，剩餘工作同時涉及 Django 統計聚合端點與 Vue 儀表板頁面，性質與 Phase 6 企業操作介面一致。

**決策**：「稽核與正確率總覽」正式併入 Phase 6，不另立新 Phase，也不回溯擴張已結案的 Phase 5。Phase 6 必須完成聚合 API、儀表板、統計期間篩選、空資料／錯誤處理、權限驗證與瀏覽器驗收，才能宣稱此功能完成。

**理由**：這是具有後端支援的可視化功能，與 Phase 6 的導覽、權限與各角色瀏覽器流程同步實作，可避免重複調整介面與驗收基礎。

**後果**：原 DRAFT 的待決排程項目移除；SPEC 與 PROGRESS 將此功能明列為 Phase 6 正式範圍。
