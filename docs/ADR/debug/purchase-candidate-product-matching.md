# 採購需求候選品項媒合除錯紀錄

## 2026-08-31 原句正式品項被 LLM 簡化後無法媒合
**現象**：自然語言明確包含 `A產品-辦公椅`，候選畫面仍顯示找不到正式品項。
**排查過程**：確認 n8n／LLM 回傳的 `product_name` 已簡化為 `辦公椅`；Django 候選解析只以該回傳值對 `products.name` 執行不分大小寫的完全相等查詢。
**根因**：原句中的完整正式品名未保留在產品對應判斷中，導致 LLM 省略產品前綴後，`辦公椅` 無法等於 `A產品-辦公椅`。
**修復方式**：在 `backend/services/inquiry_service.py` 加入 Unicode、空白及連字號正規化；完全相等未命中時，只從原句明確包含的生效正式品名中做唯一包含關係補回。多個可能值時維持未匹配，不做模糊猜測。
**驗證方式**：新增唯一補回、歧義不猜測及缺數量仍可編輯測試；目標 Inquiry Service 與候選／矩陣 API 共 26 passed，完整 Backend 349 passed；Ruff、Django check、Migration check 通過。
**未驗證範圍**：無；Robin 已以真實 n8n／Gemini 及瀏覽器重跑指定自然語言並確認正常。
